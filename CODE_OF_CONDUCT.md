# Code of Conduct

## Our standard

Securist is built in the open for people who care about **permission under change** for code and models. Participation should be constructive, technical, and safe.

## Expected

- Assume good intent; disagree on substance, not identity.  
- Prefer evidence, links, and reproduction steps over heat.  
- Respect public-source / authorized-use boundaries.  
- Keep customer data, private Operator output, and secrets out of issues and PRs.  
- Do not demand maintainers merge speculative “AI security” scope expansions.

## Unacceptable

- Harassment, personal attacks, or discriminatory language.  
- Publishing or requesting credentials, private repos, or personal data.  
- Malware, unauthorized access instructions, or offensive tooling framed as contributions.  
- Spam, drive-by fork farms, or unsolicited mass outreach using project identity.  
- Impersonating Securist, TARX, customers, or government/vendor authority.

## Scope

This applies to GitHub interactions, public community spaces representing Securist, and maintainers acting on behalf of the project.

## Enforcement

Report to **ops@secur.ist**. Maintainers may warn, edit/remove content, block, or ban. Security vulnerabilities go to [`SECURITY.md`](SECURITY.md)—not public issues when disclosure would create risk.

## Credit

Adapted from common open-source conduct norms for a security-sensitive product. We care more about **clear boundaries** than ceremony.
